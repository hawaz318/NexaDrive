Summary of Changes
1. Security Utilities & Helpers (server/src/utils)
src/utils/password.ts

src/utils/jwt.ts
: generateAccessToken (15m), generateRefreshToken (7d), verifyAccessToken, verifyRefreshToken.

2. Validation & Middleware (server/src/validations & server/src/middlewares)
src/validations/auth.validation.ts
: Zod schemas for register, login, refreshToken, changePassword, forgotPassword, resetPassword.
src/middlewares/auth.middleware.ts
: authenticateUser (JWT Bearer token verification + active user validation) and requireRole RBAC authorization.
3. Authentication Services & Controllers (server/src/)
src/services/auth.service.ts
:
register: Validates email/username uniqueness, hashes password, initializes user with 512 GB default storage quota, issues JWT tokens, logs activity.
login: Verifies user credentials, returns tokens, saves refresh token in RefreshToken table, logs activity.
refreshToken: Refresh token rotation strategy (invalidates old refresh token, issues new token pair).
logout: Revokes refresh token.
changePassword: Password verification, hash update, token invalidation.
forgotPassword & resetPassword: Token generation & secure password reset.
src/controllers/auth.controller.ts
: Controller endpoints using asyncHandler & sendResponse.
src/routes/auth.routes.ts
: Mounted under /api/v1/auth with Swagger annotations.

Phase 4: User Profile & Account Management
Building on the completed Phase 3 (Authentication & Security), this phase adds endpoints for users to view and manage their profiles, update account settings, manage linked OAuth providers, and for admins to list/manage all users.

Proposed Changes
User Validation Schemas
[NEW] 
user.validation.ts
Zod schemas for all user-related request bodies:

Schema	Fields	Purpose
updateProfileSchema	name?, username?, avatar?	Update display name, username, avatar URL
updateEmailSchema	newEmail, password	Change email (requires password confirmation)
deactivateAccountSchema	password	Self-deactivate (requires password confirmation)
adminUpdateUserSchema	role?, isActive?, storageQuota?	Admin-only user management fields
listUsersQuerySchema	page?, limit?, search?, role?, isActive?, sortBy?, sortOrder?	Admin user listing with pagination, search & filters
User Service
[NEW] 
user.service.ts
Core business logic for user operations:

Method	Auth	Description
getProfile(userId)	User	Returns full profile with OAuth providers list, storage stats, and activity summary
updateProfile(userId, data)	User	Updates name, username, avatar — validates username uniqueness
updateEmail(userId, data)	User	Changes email after password verification — validates email uniqueness
getStorageStats(userId)	User	Returns storageQuota, usedStorage, file/folder counts
getActivityLog(userId, page, limit)	User	Paginated activity history
getLinkedProviders(userId)	User	Lists linked OAuth providers (GOOGLE, GITHUB)
unlinkProvider(userId, provider)	User	Removes OAuth link — blocks if it's the only auth method (no password set)
deactivateAccount(userId, password)	User	Self-deactivate after password confirmation, revokes all tokens
listUsers(query)	Admin	Paginated user listing with search (name/email/username), filter by role/active, sort
getUserById(targetUserId)	Admin	Get any user's full profile
adminUpdateUser(targetUserId, data)	Admin	Update role, active status, storage quota
adminDeleteUser(targetUserId)	Admin	Hard-delete a user and cascade all data
User Controller
[NEW] 
user.controller.ts
Thin controller layer — validates request via Zod schemas, delegates to UserService, responds with sendResponse:

getMyProfile — GET /me
updateMyProfile — PATCH /me
updateMyEmail — PATCH /me/email
getMyStorage — GET /me/storage
getMyActivity — GET /me/activity
getMyLinkedProviders — GET /me/providers
unlinkMyProvider — DELETE /me/providers/:provider
deactivateMyAccount — POST /me/deactivate
listUsers — GET / (admin)
getUserById — GET /:id (admin)
adminUpdateUser — PATCH /:id (admin)
adminDeleteUser — DELETE /:id (admin)
User Routes
[NEW] 
user.routes.ts
All routes mounted under /api/v1/users with full Swagger JSDoc annotations:

Authenticated user routes (all require authenticateUser):

Method	Path	Handler
GET	/me	getMyProfile
PATCH	/me	updateMyProfile
PATCH	/me/email	updateMyEmail
GET	/me/storage	getMyStorage
GET	/me/activity	getMyActivity
GET	/me/providers	getMyLinkedProviders
DELETE	/me/providers/:provider	unlinkMyProvider
POST	/me/deactivate	deactivateMyAccount
Admin routes (require authenticateUser + requireRole('ADMIN')):

Method	Path	Handler
GET	/	listUsers
GET	/:id	getUserById
PATCH	/:id	adminUpdateUser
DELETE	/:id	adminDeleteUser
IMPORTANT

Admin routes are placed after /me routes in the router to prevent :id from catching "me" as a parameter.
